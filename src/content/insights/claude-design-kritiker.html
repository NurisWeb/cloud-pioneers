    01 Das Problem

    Warum KI-Design sofort auffällt

    KI-Design sieht heute nicht mehr schlecht aus, aber es ist wiedererkennbar. Der Grund: Ein Modell baut Entwürfe aus dem, was es gesehen hat, und ohne Vorlage ist das der Durchschnitt, nicht herausragendes Design. Gibst du Claude denselben Prompt wie alle anderen, landest du beim selben Durchschnitt wie alle anderen.

    Den Durchschnitt erkennt man in fünf Bereichen. Zu jedem steht in der Tabelle, woran du ihn misst.

    02 Das Konzept

    Drei Stufen, eine Schleife

    Die Lösung hat drei Stufen. Jede setzt voraus, dass Claude gutes Design sehen kann, bevor es eins baut.

    1. 01
      Stufe 1

      Vorlage und schonungsloser Vergleich

      Galerien mit Design-Systemen bekannter Seiten liefern Farbpalette, Typografie, Tailwind-Werte und Tokens zum Kopieren. Damit baut Claude entweder Neues im Stil einer Vorlage, oder es vergleicht die eigene Seite schonungslos mit einer Benchmark und benennt jede Lücke als Wert, etwa eine zu lockere Laufweite oder fehlende Höhenstufen für Flächen.

    2. 02
      Stufe 2

      Die Design-Schleife

      Ein Screenshot ist die Benchmark. Claude baut nach und startet Kritiker als Subagents, zum Beispiel einen für das Briefing, einen für Designqualität und einen für die Wirkung. Die Schleife läuft, bis die Kritiker zufrieden sind. So entstehen Seiten, aber auch Produkt-Mails als HTML.

    3. 03
      Stufe 3

      Das Design-OS

      Eine lokale Oberfläche, die Bilder über mehrere Anbieter erzeugt und die Kosten pro Bild zeigt, alle Bilder auf dem Rechner mit einem günstigen Modell verschlagwortet und Stil-Rezepte speichert, etwa für einheitliche Thumbnails.

    Offen gesagt

    Die Schleife unten habe ich selbst gebaut und an einer Testseite in unserem Design-System „Systemplan“ ausprobiert. Alle Zahlen stammen aus diesem einen Testlauf.

    Stufe 2 ist der Kern, und dort entscheidet sich alles an zwei Fragen: woran die Kritiker messen und wann die Schleife aufhört. Kritiker, die nur Noten vergeben, drehen sich im Kreis. Deshalb ergänze ich einen Kritiker, der nicht urteilt, sondern misst. Die Schleife hat fünf Schritte.

    1. 01

      Benchmark

      Die Benchmark ist ein Screenshot, der zeigt, wie es sich anfühlen soll, plus eine DESIGN.md mit den Werten des Systems. Beides geht an den Generator, also die Claude-Sitzung, die die Seite baut.

    2. 02

      Rendern

      Der Generator schreibt HTML. Ein Skript rendert die Seite in einem echten Browser, auf dem Desktop mit 1440 px und auf dem Handy mit 375 px. Viele Fehler gibt es nur in einer der beiden Breiten.

    3. 03

      Mess-Kritiker

      Der Mess-Kritiker liest die berechneten Stile und prüft Regeln: Farben aus der Palette, kein Radius, Kontrast, Laufweite, Zeilenlänge, geladene Schrift. Er irrt sich nicht und widerspricht sich nicht, aber er sieht nur, wofür es eine Regel gibt.

    4. 04

      Bild-Kritiker

      Drei Bild-Kritiker bekommen nur Screenshots, Benchmark und DESIGN.md, jeder in frischem Kontext und mit einer einzigen Frage: Trifft es das Briefing? Ist es handwerklich gut? Bleibt etwas hängen? Jeder nennt höchstens drei Befunde und markiert sie als blockierend oder optional.

    5. 05

      Filter und Stopp

      Der Filter streicht Vorschläge, die gegen das System verstoßen, und schickt den Rest zurück an den Generator. Die Schleife stoppt, wenn das Skript nichts findet und kein Kritiker mehr etwas Blockierendes meldet, spätestens nach drei Runden.

    Wichtig

    Die Noten der Kritiker sind kein Stoppkriterium. In meinem Test lagen sie nach jeder Runde zwischen 6 und 7 von 10, auch als nichts Wesentliches mehr offen war. Was zählt, ist die Liste der blockierenden Befunde.

    03 Praxis

    Die Schleife bauen

    Schritt 1: Das System aufschreiben

    Die DESIGN.md ist ein Format, das Google mit Stitch eingeführt hat: eine Markdown-Datei im Projekt, die ein Design-System für Agenten beschreibt, so wie AGENTS.md den Code. Galerien liefern solche Dateien für bekannte Seiten. Für eine eigene Marke schreibst du sie selbst. So sieht unsere aus, gekürzt:

    DESIGN.md

Ruhiges, technisches System: Papier, Tinte, ein Signal. Wirkt wie ein Bauplan, nicht wie ein Startup.

    Schritt 3: Der Mess-Kritiker

    Playwright öffnet die Seite in Chromium, und das Skript liest für jedes sichtbare Element die berechneten Stile aus. Es läuft so, wie es dasteht, mit Node 22 und npm i -D playwright@1.56.1.

    critic.mjs
    // Mess-Kritiker: rendert eine Seite und prüft sie gegen design.json.
// Aufruf: node critic.mjs seite.html [design.json]
import { chromium } from "playwright";
import { readFileSync } from "node:fs";
import { resolve } from "node:path";

const [page = "index.html", rulesFile = "design.json"] = process.argv.slice(2);
const rules = JSON.parse(readFileSync(rulesFile, "utf8"));

const browser = await chromium.launch();
const findings = [];
// Desktop und Mobil: viele Fehler gibt es nur in einer Breite
for (const width of rules.widths ?? [1440, 375]) {
const tab = await browser.newPage({ viewport: { width, height: 900 } });
await tab.goto("file://" + resolve(page));
await tab.evaluate(() => document.fonts.ready);

// Alles Messen passiert im Browser, mit den berechneten Stilen
const found = await tab.evaluate((r) => {
  const out = [];
  const add = (rule, el, detail) =>
    out.push({ rule, el: el.tagName.toLowerCase() + (el.className ? "." + String(el.className).split(" ")[0] : ""), detail });

  // Farbe als Hex, Alpha 0 ignorieren
  const hex = (c) => {
    const m = c.match(/rgba?\(([\d.]+), ([\d.]+), ([\d.]+)(?:, ([\d.]+))?\)/);
    if (!m || m[4] === "0") return null;
    return "#" + [m[1], m[2], m[3]].map((v) => (+v).toString(16).padStart(2, "0")).join("");
  };
  const lum = (h) => {
    const [R, G, B] = [1, 3, 5].map((i) => {
      const v = parseInt(h.slice(i, i + 2), 16) / 255;
      return v <= 0.03928 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4;
    });
    return 0.2126 * R + 0.7152 * G + 0.0722 * B;
  };
  const ratio = (a, b) => { const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
  // Hintergrund: erster Vorfahr mit deckender Farbe
  // Bei Verlauf oder Bild ist der Kontrast nicht messbar: null zurückgeben
  const bgOf = (el) => {
    for (let e = el; e; e = e.parentElement) {
      const s = getComputedStyle(e);
      if (s.backgroundImage !== "none") return null;
      const h = hex(s.backgroundColor); if (h) return h;
    }
    return "#ffffff";
  };

  const all = [...document.body.querySelectorAll("*")].filter((e) => e.getClientRects().length);
  const seen = new Set();
  let blocks = 0, centered = 0;
  for (const el of all) {
    const s = getComputedStyle(el);
    for (const c of [s.color, s.backgroundColor, s.borderTopColor]) {
      const h = hex(c);
      if (h && !r.colors.includes(h) && !seen.has(h)) { seen.add(h); add("farbe-ausserhalb-palette", el, h); }
    }
    if (parseFloat(s.borderTopLeftRadius) > r.radiusMax) add("radius", el, s.borderTopLeftRadius);
    if (!r.shadows && s.boxShadow !== "none") add("schatten", el, s.boxShadow.slice(0, 40));
    if (!r.gradients && s.backgroundImage.includes("gradient")) add("verlauf", el, s.backgroundImage.slice(0, 40));
    const text = [...el.childNodes].some((n) => n.nodeType === 3 && n.textContent.trim());
    if (text) {
      const fg = hex(s.color), bg = bgOf(el);
      if (/\p{Extended_Pictographic}/u.test(el.textContent)) add("emoji", el, el.textContent.trim().slice(0, 12));
      if (fg && !bg) add("kontrast-nicht-messbar", el, "Hintergrund ist Verlauf oder Bild");
      else if (fg && ratio(fg, bg) < r.contrastMin) add("kontrast", el, `${fg} auf ${bg} = ${ratio(fg, bg).toFixed(2)}:1`);
    }
    if (el.matches("p, li") && el.textContent.trim().length > 80) {
      blocks++;
      if (s.textAlign === "center") centered++;
      const lh = parseFloat(s.lineHeight) / parseFloat(s.fontSize);
      if (lh < r.body.lineHeightMin || lh > r.body.lineHeightMax) add("zeilenhoehe", el, lh.toFixed(2));
      // Zeichen pro Zeile, grob über die Breite eines "0"
      const probe = document.createElement("span"); probe.textContent = "0".repeat(10);
      probe.style.font = s.font; document.body.append(probe);
      const chars = el.clientWidth / (probe.getBoundingClientRect().width / 10); probe.remove();
      if (chars > r.body.maxChars) add("zeilenlaenge", el, Math.round(chars) + " Zeichen");
    }
  }
  const h1 = document.querySelectorAll("h1");
  if (h1.length !== r.h1.count) out.push({ rule: "h1-anzahl", el: "h1", detail: String(h1.length) });
  for (const el of h1) {
    const s = getComputedStyle(el);
    const ls = s.letterSpacing === "normal" ? 0 : parseFloat(s.letterSpacing) / parseFloat(s.fontSize);
    if (ls > r.h1.letterSpacingMaxEm) add("h1-laufweite", el, ls.toFixed(3) + "em");
    const lh = s.lineHeight === "normal" ? 1.2 : parseFloat(s.lineHeight) / parseFloat(s.fontSize);
    if (lh > r.h1.lineHeightMax) add("h1-zeilenhoehe", el, lh.toFixed(2));
  }
  // Schrift wirklich geladen? Sonst sieht der Kritiker eine Ersatzschrift.
  // Browser laden nur benutzte Schnitte, deshalb reicht ein geladener Schnitt pro Familie.
  for (const f of r.fonts ?? [])
    if (![...document.fonts].some((x) => x.family.replace(/"/g, "") === f && x.status === "loaded"))
      out.push({ rule: "schrift-fehlt", el: "document", detail: f });
  if (blocks && centered / blocks > r.centeredBlocksMax) out.push({ rule: "zentriert", el: "body", detail: `${centered}/${blocks} Absätze` });
  return out;
}, rules);
for (const f of found) findings.push({ ...f, w: width });
await tab.close();
}

await browser.close();
// Gleiche Befunde zusammenfassen, sonst ertrinkt der Generator in Wiederholungen
const groups = new Map();
for (const f of findings) {
  const key = `${f.rule}|${f.el}|${f.detail}`;
  const g = groups.get(key) ?? { ...f, n: 0, ws: new Set() };
  g.n++; g.ws.add(f.w); groups.set(key, g);
}
for (const f of groups.values())
  console.log(`${f.rule.padEnd(24)} ${f.el.padEnd(14)} ${[...f.ws].join("+").padEnd(9)} ${f.detail}${f.n > f.ws.size ? `  (${f.n / f.ws.size}x)` : ""}`);
console.log(`\n${groups.size} Befunde`);
process.exitCode = groups.size ? 1 : 0;

    Schritt 4: Die Bild-Kritiker

    Jeder Kritiker ist ein Subagent mit genau einer Frage. Wichtig ist der frische Kontext: Ein Kritiker, der beim Bauen zugesehen hat, verteidigt die eigene Arbeit. Ich habe sie im Test als Subagent-Aufrufe mit genau diesem Text gestartet. Als Datei für Claude Code sieht das so aus:

tools: Read
model: sonnet

nicht zugesehen und verteidigst nichts.

    Schritt 5: Die Schleife selbst

    Sie ist eine Anweisung an die Hauptsitzung. Der Filter steht ausdrücklich drin, denn ohne ihn setzt der Generator jeden Vorschlag um, auch die, die das System brechen.

    .claude/skills/design-loop/SKILL.md
    ---
name: design-loop
description: Baut eine Seite nach Benchmark und DESIGN.md und verbessert sie in einer Schleife aus Mess-Skript und drei Bild-Kritikern.
---

1. Lies DESIGN.md und design.json. Die Benchmark ist ein Screenshot vom Nutzer.
2. Baue die Seite (Runde 1) oder setze die gefilterten Befunde um (ab Runde 2).

4. Screenshots in 1440 und 375 px. Starte drei design-critic-Subagents
   parallel, je mit einer Frage: Briefing, Handwerk, Wirkung.

   DESIGN.md. Befunde, die mehrere Kritiker nennen, zuerst.

   Blockierendes nennt, spätestens nach Runde 3. Noten sind kein Kriterium.

   offene optionale Punkte für den Menschen.

    04 Beim Testen

    Was beim Testen passiert ist

    Alle Beispiele habe ich selbst ausgeführt. Die interessantesten Befunde kamen nicht aus dem Design, sondern aus der Schleife selbst.

    • Null Befunde, falsche Schrift

      Nach Runde 1 meldete das Skript nichts. Der Kritiker für Handwerk sah aber sofort: Die Überschrift steht in einer Ersatzschrift. Der Browser im Container konnte Google Fonts nicht laden. Lösung: Schriften lokal einbinden und eine Regel ergänzen, die prüft, ob jede Familie wirklich geladen ist.

    • Die eigene Regel war zu streng

      Die erste Fassung der Schrift-Regel fragte mit document.fonts.check() nach dem Schnitt 400. Browser laden aber nur Schnitte, die benutzt werden, und die Mono-Schrift kam nur in 500 vor. Ergebnis: ein Fehlalarm. Jetzt reicht ein geladener Schnitt pro Familie.

    • Nur Desktop geprüft, Fehler auf dem Handy

      In Runde 1 sahen Skript und Kritiker nur die Desktop-Ansicht. In Runde 2 bekamen die Kritiker auch den 375-px-Screenshot, und alle drei fanden denselben Fehler: Zwei Kacheln waren eingerückt, eine nicht. Seitdem rendert das Skript immer beide Breiten. Den Einzug findet es trotzdem nicht, das bleibt Aufgabe der Bild-Kritiker.

    • Kontrast auf Verläufen ist nicht messbar

      Die erste Version meldete weißen Text mit 1,05:1 Kontrast, weil sie den Verlauf übersah und die weiße Seitenfläche dahinter nahm. Jetzt meldet das Skript „nicht messbar“ und überlässt die Stelle den Bild-Kritikern. Ein Skript, das falsch misst, ist schlimmer als eins, das schweigt.

    • Kritiker widersprechen sich und dem System

      Für denselben Abstand schlug ein Kritiker 48 px vor, ein anderer 96 bis 120 px. Zwei wollten eine Kennzahl pro Kachel, einer einen Status-Punkt vor dem Button. Beides verbietet unser System: keine erfundenen Zahlen, Bernstein nur als Signal. Ohne den Filter hätte der Generator es eingebaut. Den Abstand hat die DESIGN.md entschieden, nicht der Kritiker.

    • Wiederholungen ertränken den Generator

      Drei gleiche Karten ergaben jeden Befund dreimal. Das Skript fasst gleiche Befunde jetzt zusammen und schreibt „(3x)“ dahinter. Die Liste für den Generator wurde dadurch ein Drittel kürzer.

    • ESM findet globale Pakete nicht

      import { chromium } from "playwright" scheiterte mit ERR_MODULE_NOT_FOUND, obwohl Playwright global installiert war. ES-Module ignorieren NODE_PATH. Lösung: Playwright lokal im Projekt installieren.

    05 Entscheidung

    Welche Stufe lohnt sich?

    SituationStufe 1: Vorlage und VergleichStufe 2: SchleifeStufe 3: Design-OS
    Neues Projekt, noch kein eigenes SystemJa: Vorlage wählen, anpassen, als DESIGN.md festhaltenNoch nicht, erst braucht es RegelnNein
    Eigenes System, die Seite wirkt trotzdem flachJa: einmal schonungslos gegen eine Benchmark vergleichenJa, für die Seiten, die du danach baustNein
    Viele Seiten, Mails oder Folien im selben StilEinmal am AnfangJa: jede neue Seite läuft durchNur bei vielen Bildern
    Viele Bilder, Thumbnails, KampagnenFür die BildspracheFür LayoutsJa: Stil-Rezepte und durchsuchbares Archiv
    Faustregel

    Fang mit dem Vergleich an. Er kostet eine Sitzung und liefert dir die Werte, die in deine DESIGN.md gehören. Die Schleife lohnt sich ab der dritten Seite im selben System, und das Mess-Skript zuerst, weil es nichts kostet und nie widerspricht.

    06 Umsetzen

    Selbsttest und Checkliste

    Drei Fragen, jede mit Erklärung. Wer sich an eine Antwort erinnern muss, behält sie länger.

    Du schreibst „mach es modern und clean“. Warum sieht das Ergebnis trotzdem nach KI aus?

    Derselbe Prompt wie alle anderen führt zum selben Ergebnis. Eine DESIGN.md oder ein Benchmark-Bild liefert konkrete Werte, die vom Durchschnitt abweichen.

    Das Mess-Skript meldet 0 Befunde. Ist die Seite fertig?

    Skript und Bild-Kritiker ergänzen sich. Noten taugen nicht als Stoppkriterium, sie blieben im Test bei 6 bis 7. Es zählt, ob blockierende Befunde offen sind.

    Ein Kritiker schlägt eine Kennzahl pro Kachel vor. Was tust du?

    Kritiker kennen das System nur aus dem Text, den sie bekommen. Der Filter schützt die Regeln, sonst baut der Generator Dinge ein, die das System verbietet.
