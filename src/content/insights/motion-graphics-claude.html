Dein Team hat einen neuen Freigabeprozess eingeführt. Die Fachabteilung will ein Schulungsvideo von einer Minute, der Vertrieb einen Spot von 30 Sekunden für die Dienstleistung dahinter. Für eine Agentur gibt es kein Budget. Ein KI-Videomodell liefert schöne Bilder, aber das Logo verzieht sich, die Oberfläche ist erfunden, und jede Korrektur ist ein neuer Versuch mit ungewissem Ausgang.

  • Mitnehmen 1Motion Graphics aus Code sind kein generiertes Video, sondern eine Webseite mit Zeitleiste, die ein Programm Bild für Bild abfotografiert. Deshalb kannst du jede Farbe und jedes Timing gezielt ändern.
  • Mitnehmen 2Für Software und Dienstleistungen ist das der bessere Weg als ein Videomodell, weil Logo, Schrift, Farben und echte Oberfläche exakt übernommen werden und Text im Bild stimmt.
  • Mitnehmen 3Prompte nach Ziel, Referenzen und Geschmack und mach wörtlich, was wörtlich sein muss: Text im Bild in Anführungszeichen, Zeitpunkte in Sekunden, Verbote ausdrücklich.

Dein Scrollen ist die Zeit

Das Bild unten ist kein Film, sondern der Code aus diesem Beitrag. Deine Scrollposition ist die Zeit t. Daneben steht, welche Werte render(svg, t) für genau diesen Moment ausrechnet. Rückwärts scrollen spult zurück. Ändere unterwegs den Versatz zwischen den drei Schritten: Das ist eine Zahl im Code, und das Video folgt ihr sofort.

t = 0.00 sBild 1 von 136

          
Versatz
            

        

      

      

        

        
01
Die Scrollposition ist t. Bei t = 0 ist alles unsichtbar. Ab 0,1 s legt eine Maske den Titel von links frei: Sie skaliert in x von 0 auf 1.

        
02
Ab 1,0 s zeichnet sich die Linie, die drei Schritte folgen versetzt: Antrag bei 1,00 s, Prüfung bei 1,45 s, Freigabe bei 1,90 s. Im Code siehst du Deckkraft und Verschiebung jedes Kastens.

        
03
Status-Punkt bei 2,50 s, Unterzeile bei 2,90 s. Beide Zeitpunkte rechnet beats() aus dem Versatz aus. Keine Uhr, kein Zufall: Für jedes t gibt es genau einen Zustand.

        
04
Ab 3,50 s steht alles. Der Rest bis 4,5 s ist Zeit zum Lesen. 4,5 Sekunden mal 30 Bilder pro Sekunde plus das Bild bei t = 0 ergeben 136 Bilder. Scroll zurück: Gleiches t, gleiche Werte.

        
05
Schalte den Versatz auf 0,15 s. Eine Zahl ändert sich, und alle Zeitpunkte danach rücken nach vorn. Ein Videomodell müsste das ganze Video neu erzeugen, hier wird nur neu gerendert.

      

    

  






  
01 Das Problem
Warum nicht einfach ein Videomodell?

  

    

      
Ein KI-Videomodell erzeugt Pixel aus einem Prompt. Für ein Getränk oder einen Turnschuh funktioniert das inzwischen gut, weil es echte Dinge sind, die das Modell tausendfach gesehen hat. Software und Dienstleistungen kann man nicht in die Kamera halten. Das Modell erfindet dann eine Oberfläche, die es nicht gibt, Text im Bild verrutscht, und das Logo sieht in jeder Szene ein wenig anders aus.

      
Motion Graphics, also animierte Grafiken aus Formen, Schrift und Bildschirmausschnitten, lösen das anders. Claude schreibt sie als Code. Der Unterschied zeigt sich vor allem, wenn du etwas ändern willst.

Für einen Werbespot heißt das: Zeig nicht die Software, sondern was sie für den Kunden ändert. Vorher drei Mails und eine Tabelle, nachher ein Antrag mit sichtbarem Status. Das lässt sich aus Formen und echten Ausschnitten der Oberfläche bauen, und genau dafür ist Code gemacht.

    

  






  
02 Das Konzept
Ein Video ist eine Webseite mit Uhr

  

    

      
Das Prinzip hat fünf Stationen. Neu ist nicht das Rendern, das gibt es seit Jahren. Neu ist, dass aktuelle Modelle wie Claude Opus 5.5 die ganze Kette selbstständig bedienen: Komposition schreiben, eigene Bilder als Screenshot prüfen, korrigieren, rendern.

      
    
        
  1. 01 Prompt
    Der Prompt beschreibt das Ziel, gibt Referenzen mit und sagt, was dir gefällt. Wie das Video technisch entsteht, muss nicht drinstehen. Das weiß das Modell, oder ein Werkzeug wie HyperFrames bringt es ihm als Skill bei.
    2. 
        
  2. 02 Komposition
    Claude schreibt eine Komposition: eine Webseite mit fester Größe, zum Beispiel 1920 × 1080 Pixel. Jede Bewegung ist eine Funktion der Zeit. Für t = 1,5 s gibt es genau einen Zustand, egal wie schnell der Rechner ist.
    3. 
        
  3. 03 Vorschau
    In der Vorschau springt Claude zu einzelnen Zeitpunkten, macht Screenshots und prüft sie selbst. Was nicht passt, wird als Korrektur im Code geändert, nicht durch einen neuen Versuch. Von hier führt der Weg also zurück zur Komposition, so oft wie nötig.
    4. 
        
  4. 04 Renderer
    Der Renderer öffnet die Seite in einem Browser ohne Fenster, setzt die Zeit auf 0, 1/30, 2/30 Sekunden und so weiter und fotografiert jedes Bild ab.
    5. 
        
  5. 05 MP4
    FFmpeg, ein freies Werkzeug für Video und Ton, setzt die Bilder und die Tonspur zur MP4 zusammen. Gleicher Code ergibt dasselbe Video, bei mir byte-genau.
    6. 
      

      
Das erklärt auch, warum Änderungen billig sind. Du zahlst nicht für ein neues Video, sondern für ein paar Tokens, in denen Claude eine Zeile ändert, und für die Rechenzeit des Renderns.

Das Werkzeug: HyperFrames

      
HyperFrames ist ein Open-Source-Framework von HeyGen (Lizenz Apache 2.0), das genau diese Kette für KI-Agenten verpackt. Es bringt Skills für Claude Code mit, also Anleitungen, die Claude bei Bedarf lädt, dazu Vorlagen und einen Renderer. Voraussetzung sind Node.js 22 und FFmpeg. So installierst du es laut README als Plugin in Claude Code:

      
Terminal
claude plugin marketplace add heygen-com/hyperframes
claude plugin install hyperframes@hyperframes

        
Danach rufst du in Claude Code /hyperframes:hyperframes auf. Ohne Agent geht es mit npx hyperframes init, preview und render.

      
Offen gesagt
HyperFrames selbst habe ich hier nicht ausgeführt: Meine abgeschottete Testumgebung blockiert das Starten fremder npm-Pakete. Die Angaben zu HyperFrames stammen aus README und Doku (Version 0.8.119). Das Prinzip dahinter habe ich mit einem eigenen Renderer aus Playwright und FFmpeg nachgebaut und gemessen, siehe unten. Ton, Sprecherstimmen und echtes Kameramaterial habe ich nicht getestet.

Aktuelle Modelle brauchen keine Schritt-für-Schritt-Anleitung mehr. Sie brauchen drei Dinge, die sie nicht selbst wissen können. Wie du Opus 5.5 allgemein promptest, steht ausführlich im Beitrag „So promptest du Claude Opus 5.5“. Hier geht es nur um das, was bei Videos dazukommt.

Die Komposition: alles aus der Zeit berechnet

      
So sieht die kleinste sinnvolle Komposition aus. Es ist dieselbe Datei, die oben in der Geschichte läuft. Entscheidend ist die Funktion render(svg, t): Sie bekommt eine Zeit und stellt den Zustand für genau diesen Moment her. Bewegt werden nur Deckkraft, Verschiebung, Maske und das Zeichnen der Linie.

    

    

      
comp.js
// Komposition als reine Funktion der Zeit: gleiches t ergibt immer dasselbe Bild.
// Kein Date.now, keine CSS-Transitions, kein requestAnimationFrame.
const CONFIG = {
  duration: 4.5,   // Sekunden
  fps: 30,
  stagger: 0.45,   // Versatz zwischen den drei Schritten in Sekunden
};

// ease-out-expo, wie auf der Website
const easeOut = (x) => (x >= 1 ? 1 : 1 - Math.pow(2, -10 * x));
// Fortschritt 0..1 eines Abschnitts, der bei start beginnt und dur Sekunden dauert
const span = (t, start, dur) => easeOut(Math.min(1, Math.max(0, (t - start) / dur)));

// Zeitpunkte aus der Konfiguration berechnen, damit eine Zahl alles verschiebt
function beats(cfg) {
  const nodes = [0, 1, 2].map((i) => 1.0 + i * cfg.stagger);
  const dot = nodes[2] + 0.6;
  return { title: 0.1, line: 1.0, nodes, dot, sub: dot + 0.4 };
}

function render(svg, t, cfg = CONFIG) {
  const b = beats(cfg);
  const q = (s) => svg.querySelector(s);
  // 1. Titel wird von links freigelegt (Maske skaliert in x)
  q("[data-mask]").setAttribute("transform", `translate(40 0) scale(${span(t, b.title, 0.9)} 1) translate(-40 0)`);
  // 2. Linie zeichnet sich, die Knoten folgen versetzt
  q("[data-line]").style.strokeDashoffset = String(1 - span(t, b.line, 0.6 + 2 * cfg.stagger));
  b.nodes.forEach((start, i) => {
    const p = span(t, start, 0.5);
    const n = q(`[data-node="${i}"]`);
    n.style.opacity = String(p);
    n.style.transform = `translateY(${(1 - p) * 14}px)`;
  });
  // 3. Status-Punkt, danach die Unterzeile
  q("[data-dot]").style.transform = `scale(${span(t, b.dot, 0.4)})`;
  const sub = span(t, b.sub, 0.6);
  q("[data-sub]").style.opacity = String(sub);
  q("[data-sub]").style.transform = `translateY(${(1 - sub) * 8}px)`;
}

if (typeof window !== "undefined") Object.assign(window, { CONFIG, beats, render });

    

    

      
Die Seite drumherum (comp.html) enthält nur das SVG mit 1280 × 720 Pixeln, die Schriften als lokale Dateien und eine Zeile, die window.__seek(t) für den Renderer bereitstellt. HyperFrames erwartet statt __seek eine pausierte GSAP-Zeitleiste in window.__timelines. Das Prinzip ist dasselbe.


      
Der Renderer: Bild für Bild

      
Der Renderer macht, was in Station 04 und 05 oben steht. Er braucht Playwright mit Chromium und FFmpeg, sonst nichts.

    

    

      
render.mjs
// Mini-Renderer nach dem Prinzip von HyperFrames: Seite Bild für Bild auf t setzen,
// Screenshot machen, mit FFmpeg zu MP4 zusammensetzen.
// Aufruf: node render.mjs out.mp4 ['{"stagger":0.2}']
import { chromium } from "playwright";
import { spawn } from "node:child_process";
import { resolve } from "node:path";

const [out = "out.mp4", override = "{}"] = process.argv.slice(2);
const cfg = JSON.parse(override);
const browser = await chromium.launch();
const page = await browser.newPage({ viewport: { width: 1280, height: 720 } });
await page.goto("file://" + resolve("comp.html"));
await page.evaluate(() => document.fonts.ready); // Schriften vor dem ersten Bild laden
const { duration, fps } = await page.evaluate(() => CONFIG);

// FFmpeg liest PNG-Bilder von stdin
const ff = spawn("ffmpeg", ["-y", "-loglevel", "error", "-f", "image2pipe", "-framerate", String(fps),
  "-i", "-", "-c:v", "libx264", "-pix_fmt", "yuv420p", "-crf", "20", out], { stdio: ["pipe", "inherit", "inherit"] });

const frames = Math.round(duration * fps);
const started = Date.now();
for (let i = 0; i <= frames; i++) {
  await page.evaluate(([t, c]) => window.__seek(t, c), [i / fps, cfg]);
  const png = await page.locator("#frame").screenshot({ type: "png" });
  if (!ff.stdin.write(png)) await new Promise((r) => ff.stdin.once("drain", r));
}
ff.stdin.end();
await new Promise((r) => ff.on("close", r));
await browser.close();
console.log(`${frames + 1} Bilder in ${((Date.now() - started) / 1000).toFixed(1)} s -> ${out}`);

04 Beim Testen
Was beim Testen passiert ist

  

    

      
Alle Zahlen hier stammen aus meinen Läufen mit dem Renderer oben, auf einem Cloud-Container mit Node 22.22, Playwright 1.56.1 und FFmpeg 6.1.1.

      
    
        
  • Eine CSS-Animation lief dreimal zu schnell
    Ich habe den Titel testweise mit einer normalen CSS-Animation über 3 Sekunden eingeblendet. Im Video war sie schon nach 1 Sekunde fertig, und zwei Läufe ergaben zwei verschiedene Dateien. Ursache: CSS-Animationen laufen nach der Uhr des Browsers, nicht nach der Zeit, die der Renderer setzt. Lösung: Jeder Zustand wird aus t berechnet. Die Doku von HyperFrames verbietet aus demselben Grund Date.now(), ungesetzte Zufallszahlen und Hover-Zustände.
    • 
      

      
Die Grafik simuliert genau diesen Fall. Ein Renderer braucht für jedes Bild eine gewisse Rechenzeit. Die CSS-Animation zählt diese echte Zeit, die Komposition aus t zählt nur Bilder. Beide blenden den Titel über 3 Sekunden ein.

Balkenhöhe: wie weit der Titel im jeweiligen Bild freigelegt ist. 77 ms pro Bild entsprechen meinem gemessenen Lauf (136 Bilder in 10,5 s), 100 ms dem dreifach zu schnellen Fall aus dem Test, 33 ms wäre Echtzeit. Die Ladezeit bis zum ersten Bild (0 bis 0,4 s) und die Schwankung der Rechenzeit um ±20 % pro Bild sind angenommene Beispielwerte.

    

    

      
    
        
  • Ohne Uhr ist das Video byte-genau gleich
    Mit der Komposition oben habe ich zweimal gerendert und die Prüfsummen verglichen: identisch. Das ist mehr als eine Kuriosität. Du kannst ein Video in die Versionsverwaltung legen, ändern und sicher sein, dass sich nur das ändert, was du geändert hast.
    • 
        
  • Zweieinhalb Sekunden Standbild
    Meine erste Fassung war 6 Sekunden lang, aber die letzte Bewegung endete nach 3,5 Sekunden. Der Rest war ein eingefrorenes Bild. Der Prompt-Leitfaden von HyperFrames nennt genau das als häufigsten Fehler. Lösung: Dauer an die letzte Bewegung koppeln (bei mir jetzt 4,5 s, also 1 s zum Lesen) oder im Prompt eine ruhige Restbewegung verlangen.
    • 
        
  • Die Linie schien durch die Kästen
    Beim Durchsehen der Einzelbilder fiel auf: Während ein Kasten einblendet, ist die Linie dahinter durch ihn zu sehen, weil die ganze Gruppe halb durchsichtig ist. In der fertigen Szene stört es nicht, bei langsamer Einblendung schon. Lösung: nur Rahmen und Text einblenden, die Füllung sofort deckend zeigen. Genau solche Dinge findet Claude, wenn es Screenshots einzelner Zeitpunkte prüft.
    • 
        
  • Rendern kostet Zeit, nicht Geld
    136 Bilder in 1280 × 720 brauchten 10,5 Sekunden, also gut doppelt so lange wie das Video selbst. Das ist eine einfache Szene ohne Kameramaterial. Mit Video im Hintergrund, Ton und 1920 × 1080 rechne mit deutlich mehr, und plane Korrekturrunden so, dass du nicht jedes Mal das ganze Video renderst, sondern nur einzelne Bilder prüfst.
    • 
      

    

  






  
05 Entscheidung
Wann Code, wann Videomodell?

  

    

      

        

          
VorhabenMotion Graphics als CodeWorauf du achtest

          
            
Short aus eigener AufnahmeGut: Schnitt, Untertitel, Grafiken zum GesagtenSchnittliste vorher freigeben. Ton aus Code klingt künstlich, lizenzfreie Musik mitgeben

            
Werbespot für Software oder DienstleistungSehr gut: echtes Branding, echte OberflächeNichts erfinden lassen, keine Zahlen, die nicht auf der Website stehen

            
Erklär- und SchulungsvideoSehr gut: Abläufe, Warnzeichen, SchritteInhalte nur aus genannten Quellen. Sprechertext vorher prüfen

            
Realistische Szenen mit Menschen oder ProduktenSchwachHier ist ein Videomodell besser. Beides lässt sich kombinieren

            
Stimme und MusikNicht der KernEigene Dateien oder einen Sprachdienst einbinden. Lizenz prüfen

          
        

      

    

    

      
Faustregel
Wenn das, was du zeigen willst, auf einem Whiteboard erklärbar ist, bau es als Code. Wenn es eine Kamera braucht, nimm ein Videomodell. Fang mit 10 Sekunden an, nicht mit einer Minute.
